Application workspace · 4 October 2026

Your documents.
A private workspace.

The portfolio and programme research are public. The Databases page loads private application progress and documents only after an invited member signs in. Members share one workspace and use individual accounts.

Where information is stored

Website accounts are managed by Supabase Auth. Application notes, checklist states, deadlines, membership and activity history are stored in the project’s Postgres database. Documents are uploaded directly to the private Supabase Storage bucket. They are not committed to the public GitHub repository. Supabase uses its own storage allowance, separate from Google Drive.

Programme files are stored by application and document type. Shared resources supply reusable files unless a programme has its own. Each upload creates a new version; the app preserves older versions. Progress backups contain notes and file references, not the document binaries. Uploading here does not submit an application to a university.

Who can access the workspace

The owner grants invitations to verified email addresses. Editors can read progress, update it, upload and download files. Viewers can read and download. Only the owner can grant or remove member access. Every member can see the shared workspace’s application data and document versions; there are no private per-member folders within it.

Database Row Level Security and Storage policies check membership on server requests. Downloads require an authenticated member; the website does not create permanently public document links. Project administrators can also access and administer the underlying project. This is not end-to-end encrypted storage.

Removing a member blocks future authorised access. It cannot take back a document already downloaded or information already viewed. Supabase’s project-level administrator access is separate from website membership.

Accounts and browser sessions

Your website password is sent over HTTPS to Supabase Auth. Use a separate website password. Supabase’s GitHub dashboard sign-in is a different account flow.

Access and refresh tokens, loaded private data and unsaved edits stay in the page’s memory. The app does not persist them in local storage, session storage or exports. The open page refreshes its session automatically; reloading requires sign-in again, except when following a valid account-confirmation or password-reset link.

Sign-out clears private fields, file lists, activity and pending in-memory changes and cancels active document requests. It does not delete saved cloud data, downloaded files, browser download history or copies other members have retained. A password manager may separately offer to save your login according to its settings.

Activity and agent access

The server records the authenticated member behind changes and uploads, their display name and whether the account is a person or agent. Progress history includes previous and new field values, including notes. The dashboard shows the latest 50 events; earlier history is retained in the database.

An agent needs a dedicated member account and uses the same permissions as other members. The website itself does not send your documents to a language model or an advertising/analytics service. If you give an agent access, that agent’s provider and the actions you request determine how it processes data it reads. No continuous agent monitoring starts merely because the workspace is connected.

Sync, earlier versions and deletion

Changes save automatically while connected. Independent fields merge. If two members update the same field, the last committed write wins; earlier values remain in the activity history. The open dashboard receives live updates and also refreshes every 30 seconds. Temporary connection failures can delay updates. Use Sync now to check the latest state.

Unsaved changes remain only in the open page. A save failure offers Retry and a private progress backup. Closing or signing out can discard unfinished work. Large uploads retry interrupted requests while the page stays open. Cancelled or interrupted uploads may leave unfinished upload records or already-arrived files for recovery.

Document versions and change history are retained until a project administrator removes them. Replacing a file, clearing a note or revoking a member does not erase historical copies. Contact the workspace owner for removal of data, document versions or the whole workspace; the owner can arrange this through the Supabase project administration tools.

Older Google Drive and browser records

Old Google Drive links keep their original sharing settings. Keeping a link here does not copy its file into Supabase or change who can access it in Google. Use its Drive link to retrieve it, or upload the actual document into this workspace.

The earlier browser tracker stored notes locally without sign-in. A notice offers to import that copy into the shared workspace or remove it. The old copy is removed only after a confirmed import. Until then it remains in that browser. No Google account connection is needed for new Supabase uploads.

Hosting and service providers

GitHub Pages hosts the public website under the GitHub privacy statement. Supabase handles account, database and Storage requests under its privacy policy. The project’s configured email provider handles account confirmations and password resets. Existing Drive links use Google’s services when opened.
