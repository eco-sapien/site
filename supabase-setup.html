Individual accounts.

Supabase handles website accounts, application progress and private document storage. Members use their own logins to access one workspace. The public portfolio and research stay on GitHub Pages.

Before the first sign-in

Finish the project connection and reserve the owner’s verified email. Signing into the Supabase dashboard with GitHub creates an administrator session; it does not create a website account or connect an agent automatically.

  1. Use the project you created

    Open EcoSapien Applications in Supabase ↗. Standard Postgres is sufficient. Keep automatic Row Level Security enabled. A region in the EU is a sensible choice for this workspace.

    If working with an agent through the Supabase connection, authorise that connection for this project so it can apply and check the setup.

  2. Create the protected workspace tables

    Apply these migrations in order through the connected Supabase tools, or paste each complete file into the project’s SQL Editor and run it:

    1. Shared workspace, membership and activity
    2. Private documents and progress updates

    They create the eco_* tables, validated update functions and a private application-documents bucket. The browser has no direct table-write permission. File paths are unique; replacing a document keeps its previous version. Check that no earlier broad Storage policy grants access to this bucket.

  3. Reserve the owner’s access privately

    Use the private owner bootstrap prepared during setup. For a separate installation, copy the bootstrap template outside the public repository. Replace its email and workspace UUID placeholders, then run that copy in the SQL Editor.

    The resulting invitation can be claimed only by an authenticated account with the same confirmed email. Keep personal email addresses and the filled-in bootstrap out of the public website repository.

  4. Configure website sign-in

    Under Authentication → URL Configuration, set the Site URL to https://www.ecosapien.de and add https://www.ecosapien.de/databases.html as an allowed redirect. Add an exact local test URL only if needed for testing.

    Enable the Email provider and keep Confirm email switched on. Set a minimum password length of 12 or more. Use the Databases sign-in window to create the owner account, confirm its email and sign in with its website password.

    Supabase’s default mail service sends only to addresses on the project’s organisation team and has a small rate limit. For ordinary invited users and reliable password resets, configure custom SMTP ↗. An administrator can also create an individually verified account directly in Auth. Do not disable email confirmation as a shortcut: invitations rely on verified email ownership.

  5. Connect the static website

    Put only these public values into assets/supabase-config.js: the project URL, its publishable key (or legacy anon key), and the workspace UUID used in the bootstrap. The project URL and public key are available in the project’s connection/API settings.

    A public key identifies the project; it does not replace user authentication or workspace membership. Never publish a secret key, a service_role key, database password, user password or session token.

    Deploy the configured website only after verifying an owner login, a second member, a private upload/download, shared progress and a denied uninvited account.

  6. Add people and agents

    After sign-in, use Databases → People & agents. Enter the new member’s email and display name, choose Editor or Viewer, and grant the invitation. Share the Databases address with them yourself; this control reserves access and does not send an invitation email. Invitations expire after 30 days.

    An agent needs its own confirmed Auth account, invited with Account for → Agent. Editors can read, upload and update; viewers can only read and download. Removing membership blocks future access under the same database and Storage rules.

    The included command-line helper, tools/agent_workspace.mjs, reads changes, uploads/downloads files and updates progress as that agent member. Store its email/password in a private environment file outside the website. It accepts public project keys only. Run node tools/agent_workspace.mjs --help for the commands. The browser and agent actions appear together in the activity log.

    Connecting the project to a chat does not start continuous monitoring. An agent reads updates when it is run; an open dashboard receives live updates with a periodic refresh fallback.

Storage, migration and recovery

Supabase Storage has its own plan allowance and billing. It does not use the 2 TB in a Google account. This workspace initially accepts files up to 50 MB each; all retained versions count toward storage usage. Check the project’s usage page as the library grows.

Older progress backups (versions 1–3) and browser notes can be imported after sign-in. Existing Drive links remain references with their original Google permissions. Upload the actual files if they should live in the shared Supabase workspace. Version 4 backups include private file IDs for the same workspace, not file contents, passwords or tokens.

Progress backups do not back up document binaries. Keep an independent copy of important documents. An interrupted upload that reached Storage can be attached with Unfinished uploads → Finish linking; if its bytes did not arrive, select the original file and upload again. Large uploads resume transient failures while the page remains open.

Verification and maintenance

Run npm ci and npm test to test catalogue rules, real PostgreSQL policies in PGlite and the client’s session/transport behavior. The optional Firefox test python3 tools/tests/check_private_workspace.py uses synthetic accounts and documents; see the repository README for setup. These local checks complement live Supabase Auth, Storage, email and Realtime checks.

Only Supabase project administrators can change the database rules or purge stored history. Keep the document bucket private. Manage stored objects through the Storage API or dashboard, rather than deleting rows directly from storage.objects.
